# 随选：UI 与交互规格

> v1.1。以下是待制作与验证的设计规格，不是已有运行截图。需求见[需求文档](requirements.md)，状态来源见[架构](architecture.md)。

## 1. 设计目标与风格

核心体验是“给出候选—执行一次—看懂结果—需要时复用”，而不是浏览复杂设置。每个工具有一个明确主操作，结果同时使用文字和图形表达。

视觉方向采用暖白背景、深色文字、橙色主操作与青绿色辅助强调；深色主题使用深灰背景和清晰对比，不直接反转全部颜色。颜色只作辅助，不能独自区分正反面、错误或选中项。

初始设计参数：页面边距 16dp、主要间距 8/16/24dp、触控区域至少 48dp、正文约 16sp、标题约 24sp、结果约 32sp。文字跟随系统缩放，实际密度与对比需在设备验证后调整。使用系统中文字体和应用原生图形，首版不依赖远程图片、字体或音效。

## 2. 导航与页面职责

| 页面 | 入口 | 必需内容 | 返回行为 |
|---|---|---|---|
| 转盘 | 底部主导航 | 候选项/字母模式、转盘或字母区、候选列表、主操作、结果 | 保留已保存草稿与模式 |
| 硬币 | 底部主导航 | 正反面可辨识硬币、文字结果、抛一次 | 不因返回重新抛掷 |
| 骰子 | 底部主导航 | 1/2/3 数量选择、点阵、每骰点数和总和、掷一次 | 配置先保存，返回恢复 |
| 灵感球 | 底部主导航 | 默认/自定义模式、答案管理、揭示区、问一次 | 保留答案与模式 |
| 历史 | 顶栏统一入口 | 工具筛选、列表、空状态、清空操作 | 返回原工具与原结果 |
| 历史详情 | 历史条目 | 原请求快照、完整结果、时间、模板摘要 | 不提供隐式重抽 |
| 模板 | 顶栏统一入口 | 模板列表、示例导入、创建/编辑/套用/删除 | 脏表单先处理 |
| 设置 | 顶栏统一入口 | 跟随系统/浅色/深色、减少动画、应用说明 | 改动立即反馈，失败明确 |
| 编辑页/面板 | 新增/编辑操作 | 标签、输入、计数、字段错误、保存/取消 | 保存后离开/放弃/继续编辑 |

字母属于转盘页的模式，历史中以独立工具类型标记。四个主工具入口维持稳定位置，不把模板或历史混进工具名称。处理中仍可导航；离开时可结束装饰动画，保存结果不取消或重抽。

## 3. 转盘纵向布局

从上到下为页面标题与历史/模板/设置入口、模式切换、主要图形与完整结果、主操作、候选列表及新增/模板操作。窄屏允许整页滚动，主操作不能被键盘永久遮挡。

- 候选列表显示序号、文本和编辑/删除入口；序号与扇区顺序一致。初版不提供拖拽，避免暗含尚未实现的排序行为。
- 小扇区可截断标签；完整候选在列表可读，最终结果完整显示，必要时换行或打开详情。
- 空池展示“添加第一个选项”，主抽取不可用；唯一候选展示“只有一个选项，本次会选中它”，直接揭示。
- “保存模板”只处理已保存草稿；脏表单必须先完成保存。更新原模板与另存为具有明确按钮名称。
- 字母模式说明范围为 A—Z，使用大字揭示即可，不强求 26 个拥挤扇区。

## 4. 各工具交互

### 硬币

两面不仅改变颜色，还显示“正/反”或不同符号与文字。翻转动画结束时朝向、结果文字与历史一致；读屏直接宣读本次结果。重复点击不多抛一次。

### 骰子

数量选择为明确的 1、2、3，不使用无上限输入。各骰点阵可分别识别，显示“第 1 个：…，第 2 个：…；总和：…”。数量改变不改写旧结果的数量；新的配置在下一次操作生效。

### 灵感球

默认/自定义模式可见；管理入口展示当前自定义条数。空自定义池提供新增入口并禁用抽取，界面不得显示来自默认池的假结果。单答案不故作不确定，直接显示唯一项；完整答案可换行。

### 模板

套用前若当前有未保存编辑，先处理编辑。套用复制内容，界面可以显示来源模板及“已修改”状态；删除来源模板后仍保留当前草稿，并把“更新原模板”改为可另存的提示。示例导入由用户触发并处理重名。

## 5. 状态呈现与文案

| 状态 | 页面反馈 | 可以操作 | 禁止行为 |
|---|---|---|---|
| Empty | 无选项/自定义答案为空及添加入口 | 编辑、切工具 | 抽取 |
| Ready | 当前输入和主操作 | 抽取、编辑、模板、历史 | 把未保存表单当有效输入 |
| Preparing/Saving | 主按钮忙状态，简短“正在保存本次结果” | 导航离开 | 第二次抽取、改配置、套用、清历史 |
| Animating | 已保存结果的短展示 | 离开，或减少动画时直接揭示 | 重新随机、重复写入历史 |
| Revealed | 完整结果与再次操作 | 新抽取、编辑、历史 | 动画回调触发新提交 |
| SaveError | “结果未确认保存”，重试入口和明确原因 | 重试确认/保存、返回 | 显示成功或自动另抽 |
| Conflict | 保留输入，提示数据已变化 | 重新载入/重选 | 静默覆盖或自动重抽 |
| Loading/Error | 数据加载进度或可重试读取失败 | 重试、返回 | 读失败当作空库播种覆盖 |

用语针对用户行为，不在产品页面展示 Token、线程编号、数据库事务或调试开关。“灵感球”说明为随机回答，不把开发过程反思写进 App。

## 6. 动画与生命周期

- 动画只消费已保存结果，最终姿态必须由相同结果决定。转盘几何规范见架构文档，UI 不另算第二套索引。
- 时长与圈数是固定范围内的装饰设计，不影响概率。正式实现后用可操作性验证，不以长等待营造随机性。
- “减少动画”在当前或下一次展示直接揭示，行为应在实施时统一；建议修改设置后结束当前装饰展示，不改变已保存结果。
- 旋转屏幕或返回页面可直接揭示旧结果；切后台后不强制重放长动画。进程重启只恢复已提交数据。
- 保存失败时不播放成功动画，动画完成回调不进行数据库写入。

## 7. 验证与设计交付

先交页面关系、主要布局和关键状态，再交可点击静态界面，最后接入真实事件。每页记录正常、空、忙、错误和取消状态；不只提供一张漂亮的默认页。

设计验收至少覆盖：长候选/答案、20 项候选、系统大字体、窄屏和横屏、键盘、系统返回、48dp 点击区域、颜色之外的状态标记和读屏结果描述。关键检查见 [AC15、AC16](testing/acceptance.md)。

P2 分享卡仅从保存快照生成，显示工具、结果和日期；系统分享取消或失败不改变抽取、不再次记录历史。未启动 P2 时不展示空分享入口。
