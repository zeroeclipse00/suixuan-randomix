# 开发记录与公开规则

## 双层记录

本地保留完整的用户与助手可见对话、具体任务、实现文件、失败修复、验证命令和实际 Token 明细。公开仓库只保存经检查的工作摘要、业务决策、验证结论和聚合统计。

原始记录位于被忽略的 `docs/vibe-coding/`，不作为公开 Markdown 链接目标。公开摘要不能冒充原始对话全文；实验交接如需原文，通过受控方式另行提供脱敏副本。

## 允许公开

- 需求、架构、模块、交互、验收和复现说明。
- 确实发生的工作、失败修复与验证摘要。
- 不含会话、响应和个人标识的阶段 Token 聚合。
- 通用同步脚本和不含真实值的配置示例。
- 后续经过检查的源码与应用自带素材。

## 留在本地

- 原始对话、逐响应 Token、会话或响应 ID、日志文件定位及个人文件系统路径。
- 课程课件、论文附件、实验报告和未经检查的截图录屏。
- 账号凭证、访问令牌、私钥、签名文件、真实环境变量和本机配置。
- 构建输出、缓存、数据库与个人测试数据。

这些文件由 `.gitignore` 排除，不使用强制添加绕过规则。图片按来源与目录管理，不全局排除应用所需的公开图标。

## 每轮发布前

1. 更新本地工作轨迹，登记主阶段，运行同步并检查数据边界。
2. 公开摘要只记实际工作和状态，不复制未经检查的原文。
3. 运行聚合导出，再检查公开文件的路径、标识、账号、密钥与链接。
4. 查看暂存清单与内容，验证敏感文件仍被忽略。
5. 核对提交者身份。默认可使用 GitHub noreply 邮箱；用户明确指定提交邮箱时使用其指定值，并了解该值属于公开提交元数据。
6. 从远端读取仓库状态、提交与文件清单，核对实际发布内容。

`.gitignore` 只控制未跟踪文件；若误入暂存或历史，须在发布前处理，不能只新增 ignore 后继续提交。
