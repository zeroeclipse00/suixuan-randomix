# 随选：工作阶段与执行约定

> v1.1。阶段只表示工作边界、依赖和 Token 归属，不安排日期、工期或时间任务表。业务任务详见[模块清单](modules.md)。当前正在实施框架和首条纵向流程，实际验证范围见[交接说明](handoff.md)。

## 1. 执行顺序与交接

先建立记录和可运行骨架，再验证领域/数据契约，完成转盘纵向流程，随后复用到其他工具，最后整合模板、设置与交付。M00 和 M11 持续开展，不能等全部页面完成后再补日志和测试。

M10 的静态设计可与环境检查并行；实际数据绑定须等待相应领域契约。M04—M07 可在共同抽取流程稳定后独立实施；M08/M09 可以先提供最低限度存取，完整管理放在 ST-05。不得把依赖推迟到“最后集成”而用固定成功提示临时代替。

| 依赖入口 | 先满足的契约 | 再开展 |
|---|---|---|
| 记录与骨架 | M00 记录可追溯，M01 工程可构建 | 所有业务任务 |
| 随机与提交 | M01 持久化、M02 请求/结果/协调器 | 转盘真实纵向流程 |
| 真实纵向流程 | 保存后展示、失败重试、历史一条、恢复不重抽 | 硬币、骰子、灵感球、字母 |
| 快照与版本 | 草稿、模板、答案整体写入与版本冲突 | 模板/历史完整管理 |
| 全部 P0 验收 | 核心行为与记录可核验 | P1 不重复抽签 |
| P1 或明确放弃 P1 | 选做范围记录清楚 | P2 分享卡，可不启动 |

## 2. 八个工作阶段

### ST-00 需求方案与记录机制

- **输入：** 课程材料、已确认选题和记录要求。
- **工作：** 维护 R01—R16、范围/优先级、13 模块接口、验收矩阵；建立 M00 私有原始记录和公开脱敏摘要的衔接。依据用户授权整理公开仓库，但不把仓库创建等同于 App 完成。
- **产物：** 分文件方案、真实状态入口、记录协议与阶段归属。
- **出口：** 文档相互链接可读，所有任务是计划或真实状态；正式记录边界、来源、去重和缺失口径明确。文档检查只证明文档，不填写 App 验收通过。

### ST-01 环境与 UI 设计

- **前置：** ST-00 范围可执行。
- **工作：** M01 检查并锁定实际环境、建立最小骨架；M10 明确导航、字段、状态与视觉规范，制作静态页面。
- **产物：** 可安装骨架、版本说明、页面/状态设计和基础组件。
- **出口：** 实际构建安装有证据；原型涵盖五类工具、模板、历史和错误状态。环境缺项必须先解决或说明，不能宣称已具备。

### ST-02 领域模型与随机引擎

- **前置：** 工程骨架与核心类型。
- **工作：** M01 数据模型、事务与仓储；M02 随机源、快照、结果合法性、角度映射、操作锁及保存重试。M11 同步验证领域和数据层。
- **产物：** 可替换随机/仓储边界、单次提交和独立测试。
- **出口：** 范围/角度测试、幂等、版本冲突、事务失败和快照均有实际证据；数据库能保存并读取一次合法抽取。

### ST-03 转盘完整流程

- **前置：** ST-02 抽取与提交契约稳定。
- **工作：** M03 串联候选编辑、草稿保存、冻结、抽取、事务、动画、结果与最小历史；M09 提供查询，M10 补正常/失败状态。
- **产物：** 一条真实可演示的端到端流程。
- **出口：** 输入四候选并编辑后抽取，图形/文字/历史一致，重启保留；连点、失败、返回和重建不会重复随机或写入。

### ST-04 其他工具

- **前置：** ST-03 统一流程经验证，可复用。
- **工作：** M04 硬币、M05 骰子、M06 答案池、M07 字母；复用协调器，不复制出四套互不一致的存储逻辑。
- **产物：** 五类工具真实操作和各自历史快照。
- **出口：** 正反两面、骰子数量/点阵/总和、答案模式/空池/单项、A/Z 边界和工具切换均通过对应验证；未知检查仍列未验证。

### ST-05 模板历史与设置整合

- **前置：** 核心工具及快照行为稳定。
- **工作：** M08 模板管理与套用/更新/另存，M09 筛选/详情/清理/容量，M10 主题/减少动画/全局返回与输入处理。
- **产物：** 可重用情境、完整历史与统一设置。
- **出口：** 模板或答案变化不改写过去；版本冲突不覆盖；清理与旧回调不冲突；设置不影响概率或业务存储。

### ST-06 测试修复与可选增强

- **前置：** 全部 P0 有真实实现，验收逐项执行。
- **工作：** M11 执行领域、数据、UI、生命周期与连续操作检查，处理缺陷并回归；P0 通过后可启动 M08/M02 的 P1，再按范围决定 M10 的 P2。
- **产物：** 需求—用例—结果—证据表，问题与回归记录；选做有启动/放弃决策。
- **出口：** P0 无阻断演示/数据正确性问题；已启动选做也有完整规则和证据。不能只画选做界面而声称实现。

### ST-07 复现交付

- **前置：** 核心验收和范围冻结。
- **工作：** M12 干净目录构建、固定提交/APK 校验、交接说明、真实视频、报告；M00 汇总阶段用量并检查公开材料。
- **产物：** 源码与公开过程证据、可运行交付、1—2 分钟视频、不超过 6 页报告，以及受控私有证据交接说明。
- **出口：** 源码、构建、视频和报告对应同一版本；公开材料不泄露隐私，私有证据没有因脱敏被删除；统计截止和缺失范围明确。

阶段可迭代返回。例如 ST-04 发现随机契约问题，修复调用归属其实际工作的主阶段并记录原因；不能为了“阶段完成率”隐藏回退。

## 3. 单项任务模板

每次交给成员或 AI 的任务，至少填写以下内容：

```text
任务编号：Mxx-yy；主阶段：ST-xx；优先级：P0/P1/P2
关联需求与验收：Rxx，ACxx，TCxx
当前真实行为与问题：
需要阅读的仓库相对文件与模块契约：
本次要改变的行为、输入和输出：
边界、失败、恢复和不得破坏的不变量：
前置依赖与可独立完成部分：
预期验证、实际命令/条件与判定标准：
实际修改/结果/证据与未完成项：
状态与工作编号：计划/进行中/已实现/已验证/失败/放弃
```

先给出可检验行为，再做小步实现、审阅差异和相关验证。一次优先完成一个有出口的变化，避免用一条笼统提示生成整个应用后才检查。

## 4. 记录与阶段 Token

私有原始材料在本地 `docs/vibe-coding/` 保留；公开摘要只使用工作、任务、需求、验收编号与提交定位，不包含本机路径和会话标识。根 README 提供当前实际公开记录入口。

- 每次可获得的调用保留来源、模型、输入、输出、总量和统计时间；私有保留去重标识，公开按阶段汇总。
- 同一调用只有一个主阶段，无法确定则标为未分类并说明，不能任意按比例拆分。子代理包括复用代理的本轮工作，排除继承副本和无关调用。
- 失败、重试、废弃方案纳入已知用量；供应商累计快照不直接相加，缓存/推理子项不重复加入总量。
- 未知为 `null/不可获取`，已知为零与未知分开；估算单列，不与精确值混成实测。Token 表不等于费用账单。
- 当前最终回复和迟到用量未覆盖时注明截止快照，后续补齐。每次公开汇总都说明覆盖范围与统计截止。
- 脱敏摘要不能代替私有原文。通过工作编号保存映射，实验三按课程允许方式受控交接；详细同步与配置不公开含个人信息的路径。

## 5. 分工、范围变更与完成判定

可按产品/UI、数据/领域、测试/过程三条工作线协作；人数较少时合并职责。每位成员维护自己的真实操作记录，核心随机与数据契约交叉审阅，不以谁生成代码判定谁完成验收。

范围变化记录原因、受影响的 R/M/AC、数据和 UI 影响、阶段归属及采用/放弃结论。增加外部服务、复制代码、引入资源或变更依赖必须记录来源与验证；不得在公开仓库包含访问凭证。

“已实现”需要实际产物；“已验证”需要记录条件下的真实通过证据。失败保留，修复追加，不为改善叙事删掉原始记录或制造未发生的问题。最终限制应具体到无法复现的步骤、缺失用量或未运行的设备检查。
