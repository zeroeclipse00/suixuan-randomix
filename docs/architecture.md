# 随选：架构与数据契约

> 方案 v1.1；以下均为待实施设计。范围与产品规则见[需求](requirements.md)，模块边界见[模块任务](modules.md)。

## 1. 技术边界

首版保持单个 Android 应用模块，以包组织职责，不建立微服务、多模块插件体系或后台任务队列。

| 层 | 选择 | 约束 |
|---|---|---|
| 工程 | Android、Kotlin、Gradle Wrapper | 实施前记录兼容的 JDK、SDK、插件和依赖版本，不能假定本机已具备 |
| UI | Compose、Material 3、ViewModel | 只发送事件和呈现状态，不调用随机源、不直接写数据库 |
| 领域 | 纯 Kotlin 类型与函数 | 输入校验、随机选择、角度映射可脱离 Android 测试 |
| 持久化 | Room | 抽取输入、模板、答案、历史和可选会话统一事务边界 |
| 偏好 | DataStore 或单一简单偏好存储 | 仅主题、减少动画、上次工具；不得把抽取所需配置拆到第二个存储 |

包建议为 `ui`、`domain`、`data`、`navigation`；测试对应各职责。可使用手工依赖注入，不为首版引入额外依赖注入框架。参考 [Compose 官方文档](https://developer.android.com/compose)和 [Room 官方文档](https://developer.android.com/training/data-storage/room)，具体版本以真正构建验证结果锁定。

## 2. 数据模型

| 对象 | 必需字段 | 不变量 |
|---|---|---|
| ChoiceItem / AnswerItem | 稳定 ID、显示文本、规范化比较键、position | 池内不重名；位置显式且连续；编辑保留 ID |
| ToolDraft | 工具/模式、候选列表或骰子数、答案模式、revision、来源模板 ID/版本 | 表示已保存输入；每次成功修改 revision 加一 |
| DecisionTemplate | ID、名称、revision、完整候选列表、更新时间 | 更新原模板增版本；套用复制列表，不与草稿共享可变引用 |
| AnswerPool | 池 ID、默认/自定义类型、revision、答案列表 | 默认池只读；自定义空池是合法配置但不可抽取 |
| DrawRequest | draw_id、tool、输入快照、配置、来源模板 ID/版本、可选会话 ID/版本、snapshot_version | 构造后不可变；包含顺序和可读文本，不能只存来源 ID |
| DrawResult | draw_id、工具、选中 ID/索引及文本，或硬币面、骰点数组、字母 | 必须与对应请求匹配；骰子总和由点数计算 |
| HistoryRecord | sequence、请求快照、结果快照、提交时间 | draw_id 唯一；sequence 表示提交顺序；来源删除不级联删除历史 |
| DrawSession，P1 | ID、来源快照、remaining IDs、selected IDs、revision | 两池不交叠，合并等于原快照；剩余顺序稳定 |
| AppSettings | 主题、减少动画、上次工具 | 不参与抽取事务；读失败时可使用明确默认值 |

时间保存为通用时间值，展示时按设备本地时区格式化。历史排序使用 `sequence DESC`，避免设备时钟变化破坏顺序。

快照存储方式可采用 Room 字段与有版本的序列化字段组合，先实现 `snapshot_version=1`。保存数据库 schema；升级需要明确迁移，不能用静默清库规避迁移错误。遇到无法识别的快照版本，详情提示不支持并保留原数据，不尝试猜测或覆盖。

## 3. 模块接口契约

下表是语义契约，实施可调整语言签名，但不能删去结果、不变量或错误条件。采用简单的密封结果类型即可，不建设通用工作流框架。

| 接口 | 输入与输出 | 错误与责任 |
|---|---|---|
| InputValidator | 文本、完整列表、工具配置 → 合法值或字段错误 | 空白、重复、超限、非法数量；UI 与领域共用规范化逻辑 |
| RandomSource.nextInt(bound) | 正整数 bound → `[0, bound)` | bound 非法立即拒绝；生产实现与测试实现仅在组装层替换 |
| DrawEngine.generate(request) | 不可变请求 → 结果 | 验证工具与配置；每次新操作只调用一次；不访问 UI/数据库 |
| WheelLayout.rotationFor(index, count, startRotation) | 合法索引、数量、当前角 → 终点角与选中中心 | 只做几何映射，不调用随机源；结果不越界 |
| DraftRepository.save(expectedRevision, replacement) | 完整已校验输入 → 新草稿版本 | Conflict 或 StorageError；保存成功后才更新可抽取列表 |
| TemplateRepository.create/update/delete/apply | 创建/修改命令及预期版本 → 新模板或草稿 | NotFound、Conflict、ValidationError、StorageError；apply 原子替换草稿 |
| AnswerRepository.save(expectedRevision, items/mode) | 完整答案变更或模式 → 新版本 | 空自定义池允许保存；抽取入口负责禁用；不得回退默认池 |
| DrawRepository.commit(envelope) | 同一请求＋结果 → Committed 或 AlreadyCommitted 的实际记录 | ValidationError、Conflict、StorageError；同 ID 不同内容拒绝 |
| DrawRepository.find(drawId) | 当前待确认 ID → 已提交记录或明确不存在 | 读取失败与不存在分开，不能读失败就重插 |
| HistoryRepository.list/detail/clear | 工具筛选、分页游标或确认清理命令 → 记录/结果 | 清理只影响历史；详情依赖快照，不查询当前模板拼装 |
| DrawCoordinator | 页面事件 → UiState | 管理单次操作锁、同结果保存重试、旧回调过滤和生命周期恢复 |

普通抽取采用已经冻结的输入，不因后续来源模板删除而拒绝合法快照。`revision` 检查主要用于草稿/模板/答案修改及 P1 会话提交，不能把快照重新绑定到当前来源对象。

## 4. 状态与事务

### 4.1 正常路径

1. 页面事件处理器先同步关闭入口，然后再启动异步工作；仅在协程内设置锁不足以阻止同一帧连续点击。
2. `Preparing`：读取已提交的草稿和配置，生成 draw_id，深复制为 DrawRequest；保存中的表单先完成保存，不能用屏幕上未提交的半份数据抽取。
3. 调用一次 DrawEngine，保留不可变 envelope（request＋result），进入 `Saving`。不提前揭示结果。
4. `commit` 在同一 Room 事务中校验 envelope、插入唯一历史、执行可选会话 CAS 更新，并裁剪超过 1000 条的最早历史。任何一步失败全部回滚。
5. 成功后使用仓储返回的实际记录进入 `Animating`。普通转盘计算几何终点，硬币/骰子展示相同结果；减少动画或单项池直接 `Revealed`。
6. 揭示后解除锁。下一次点击才生成新的 draw_id；完成动画或重新组合 UI 不写历史。

### 4.2 幂等与变更冲突

- `commit` 先按 draw_id 查询；若请求与结果内容完全相同，返回原记录。若相同 ID 携带不同内容，返回错误，绝不覆盖。
- 一次候选/答案列表变更在事务内整体校验、写入、重排位置并增加版本，防止只保存半张列表。
- 模板编辑和草稿更新带 expectedRevision。冲突时保留编辑表单，展示重新载入入口；不以最后写入静默覆盖。
- P1 会话更新要求 expectedSessionRevision 与当前一致，且结果 ID 属于剩余池。失败时历史也不得落库；刷新会话后由用户重新发起，不能偷偷重抽。
- DrawCoordinator 串行处理抽取、模板套用和历史清理。处理/展示期间冲突按钮禁用；数据入口仍校验忙状态，不能只靠按钮灰色。
- 已完成请求不接受再次提交。历史清理/裁剪后，旧回调也不能把已删除记录重新插回；幂等范围是当前待确认操作及仍保留的记录，而不是永久可重放所有旧命令。

### 4.3 失败与恢复表

| 场景 | 行为 | 验收重点 |
|---|---|---|
| 空池或非法输入 | 保持 Empty/Ready，给字段提示，不生成 ID 或调用随机源 | 没有历史与半成品 |
| 已知事务回滚 | SaveError 保留同一 envelope，允许重试保存 | 重试不再次抽样 |
| 返回前中断，提交结果不明 | 先 find(draw_id)；存在则恢复原记录，确认不存在才重存同 envelope | 读失败不能等同于不存在 |
| 存储持续不可读 | 保持明确错误，可离开页面；不声称保存/撤销成功 | 没有虚假成功动画 |
| 表单/模板版本冲突 | 保留用户输入并要求刷新/重选；不自动覆盖或重抽 | 历史与输入一致 |
| 动画时旋转屏幕 | ViewModel/SavedState 恢复 draw_id 与展示状态，可直接揭示 | 结果与历史各一条 |
| 切后台或离开工具 | 结束装饰动画并解除展示锁，返回揭示相同记录 | 不阻塞其他页面，也不重抽 |
| 进程在提交前终止 | 不恢复未提交操作；已保存草稿保留 | 不声称抽取成功 |
| 进程在提交后终止 | 从数据库恢复最近已提交记录，不重放命令 | 不新增历史 |
| 清空历史后重建页面 | 当前内存结果可显示，重启只读现有数据库 | 不把结果自动补回历史 |
| 偏好读取失败 | 使用默认主题/动画并提示可重试，核心抽取仍依赖正常 Room | 不丢业务数据、不静默清库 |

不为首版建设 outbox、持久任务队列或自动重放机制。未提交结果从未向用户宣称成功，因此进程终止可丢弃；已提交结果由数据库负责恢复。

## 5. 随机与角度算法

N 大于 1 的离散选择调用无偏的 `nextInt(N)`；N 等于 1 直接返回唯一项，不消耗随机源。禁止空池调用，不使用四舍五入、颜色面积或随机动画时长选择结果。骰子分别调用 `nextInt(6)+1`，字母使用 `A + nextInt(26)`。P1 从剩余 ID 列表等概率取一项，按稳定 ID 移出，保留其他项顺序。

转盘统一使用角度制，屏幕顺时针为正；指针固定在顶端 `p=-90°`，首扇区边界 `s=-90°`。N 个扇区的宽度 `w=360°/N`，索引 k 的中心 `c=s+(k+0.5)w`。要求最终旋转角模 360° 等于 `p-c`。

给定当前旋转角 r，先将目标和 r 归一到 `[0,360)`，取顺时针最小差，再加固定完整圈数作为装饰；最终角为 r 加该差与完整圈数。抽中的索引和快照顺序保持不变。单项/减少动画不需要完整圈数。

单元测试对 N＝1、2、3、7、20 的每个 k 检查旋转后的中心与指针在允许浮点误差内重合；UI 再验证实际 Canvas 方向、扇区起点、标签与公式一致。概率规则由算法和随机源边界证明，不用少量频数接近相等替代正确性证据。

## 6. 完成边界

架构完成不以“画出分层图”为准。至少需要：可独立运行的领域测试、数据库事务/幂等/快照验证、保存失败与生命周期验证，以及模块使用相同契约的证据。具体待执行项目见[验收文档](testing/acceptance.md)。
